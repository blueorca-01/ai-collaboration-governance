## 제1조(목적 및 적용 범위)

① **목적:** 이 문서는 PROC-001에 따라 작성하는 실행 지시 문서의 구성·형식·문체 및 출력·전달 규격을 정하여, 실행 AI가 작업의 대상·산출물·수행 조건·변경 허용 범위 및 완료 기준을 대화 이력 없이 명확히 이해할 수 있도록 하는 것을 목적으로 한다.

② **적용 대상:** 이 문서는 PROC-001 제8조에 따라 컴파일하는 실행 지시 문서에 적용한다. 실행 지시 문서가 다루는 작업은 논문·게임 등 프로젝트 전체에 한정되지 않으며, 논문의 특정 장, 게임의 개별 오브젝트, 코드의 특정 기능 등 사용자가 지정한 개별 작업 단위를 포함한다. 작업 단위의 크기와 관계없이 이 문서의 양식을 동일하게 적용한다.

③ **작성 및 출력 환경:** 실행 지시 문서는 PROC-001 제8조에 따라 컴파일하여 작성한다. PROC-001의 완료·승인 요건을 충족한 실행 지시 문서는 Markdown(`.md`) 파일로 출력한다.

④ **다른 규정과의 관계:** 논의 과정의 승인·상태 변경·실행 절차는 이 문서에서 새로 정하지 않으며 GOV-001 및 PROC-001의 해당 규정을 따른다. 근거의 분류·신뢰도 및 확인되지 않은 자료·가정의 표기는 TPL-003을 따른다.

## 제2조(작성 언어·파일 형식 및 식별)

① **작성 언어:** 실행 지시 문서는 한국어로 작성한다. 널리 통용되는 한국어 기술 용어는 한국어 표기만 사용할 수 있으며, 그렇지 않은 기술 용어는 처음 등장하는 위치에서 한국어 표현과 원어를 병기하고 이후에는 의미가 명확한 경우 한국어 표현만 사용할 수 있다. 통용 여부의 판단이 어려우면 병기한다.

② **원문 유지:** 다음 각 호는 번역하거나 바꾸어 쓰지 않고 원문 그대로 표기한다.

1. 파일명·폴더명·경로
2. 원본 자료의 시트명·열 이름·제목·식별자(ID) 등 실행 AI가 원본과 대조해야 하는 명칭
3. 코드·명령어·함수명·변수명·수식
4. 원문 인용

③ **파일 형식:** 실행 지시 문서는 Markdown(`.md`) 파일로 출력하고, 문자 인코딩은 UTF-8을 사용한다.

④ **파일명:** 실행 지시 문서의 파일명은 `작업지시_`로 시작하고, 그 뒤에 지시 목표와 작성 기준일(`YYYYMMDD`)을 밑줄(`_`)로 구분하여 붙인다. 파일명에는 공백과 대괄호 등 특수문자를 사용하지 않는다. 예: `작업지시_논문2장작성_20261008.md`.

⑤ **산출물과의 구분:** 실행 지시 문서의 파일 형식은 해당 지시에 따라 생성되는 실제 작업 산출물의 파일 형식과 구분한다. 작업 산출물별 종류·수량·형식 등은 PROC-001 제8조제1항제2호에 따라 실행 지시 문서에 명시한다.

⑥ **플랫폼 독립성:** 실행 지시 문서는 PROC-001 제8조제4항에 따라 플랫폼 독립 Markdown으로 작성하며, 구체적으로 다음 각 호를 따른다.

1. 표는 Markdown 표 문법으로 작성하고 HTML 태그를 사용하지 않는다.
2. 토글·콜아웃·페이지 멘션 등 특정 편집 도구의 전용 요소를 사용하지 않는다.
3. 도구별 실행 방식이 필요한 경우에는 본문과 분리된 부록에 둔다.

## 제3조(문서 머리말)

① **문서 제목:** 실행 지시 문서의 첫 줄에는 Markdown 최상위 제목(`#`)으로 실행 지시 문서의 제목을 기재한다. 제목은 작업 대상을 구체적으로 식별할 수 있도록 작성한다.

② **머리말 표:** 제목 다음에는 Markdown 표 문법을 사용한 2열 표를 배치한다. 첫 번째 열에는 항목명을, 두 번째 열에는 해당 값을 기재하며, 다음 각 호의 항목을 순서대로 배치한다.

1. **작성 기준일:** 실행 지시 문서를 컴파일한 날짜(`YYYY-MM-DD`). 파일명의 일자와 일치시킨다.
2. **작업 목적:** 이번 지시를 통해 달성하려는 핵심 목표를 간결하게 기술한다.
3. **작업 범위:** 이번 지시의 적용 대상 및 제외되는 범위를 요약한다.

③ 삭제

④ **작성 원칙:** 머리말에는 작업 식별과 개요 파악에 필요한 정보만 기재한다. 산출물 상세 명세·변경 지시·검증 기준 등은 본문에 두며, 머리말과 본문의 목적·범위가 서로 일치해야 한다.

⑤ **Markdown 형식:** 머리말은 제2조제6항의 플랫폼 독립 Markdown 원칙을 따르며, 제목과 2열 표 외의 요소에는 같은 항 제2호를 적용하고 HTML 태그를 사용하지 않는다. 표의 내용이 길면 셀 안에서 줄바꿈을 강제하지 않고 간결한 문장으로 정리한다.

⑥ **표준 작성 예시:** 다음 예시의 제목 수준·열 구성·항목명·순서를 기본 양식으로 사용한다. 대괄호 안의 값은 실제 작업 내용으로 바꾼다.

```markdown
# [작업명] 실행 지시 문서

| 항목 | 내용 |
| --- | --- |
| 작성 기준일 | 2026-10-08 |
| 작업 목적 | 논문 제2장의 이론적 배경과 선행연구 서술 개선 |
| 작업 범위 | 제2장 본문과 관련 인용·참고문헌 정합성 검토 및 수정. 다른 장의 본문 수정은 제외 |
```

## 제4조(본문의 기본 절 구성)

① **구성 원칙:** 실행 지시 문서의 본문은 실행 AI가 작업을 수행하고 검증하는 데 필요한 정보로 구성한다. PROC-001의 논의 경과·대안 비교·미승인 제안은 원칙적으로 실행 지시 본문에 수록하지 않는다. 다만 정확한 수행이나 재발 방지에 필요한 결정 근거·제약·검증 조건은 남긴다.

② **표준 절:** 본문은 다음 각 호의 절로 구성한다. 세부 항목의 수와 깊이는 작업 단위에 맞추되 PROC-001 제8조제1항의 필수 지시 사항은 빠짐없이 반영하며, 각 사항의 반영 위치는 부록 C의 대응표에 따른다.

1. **작업 목적·대상 및 입력 자료:** 작업의 목적, 원본의 파일명·버전·위치 또는 식별 방법, 참조 자료, 작업 대상과 적용 위치, 착수 전 확인 사항 및 불일치 시 중단 조건을 기술한다. 관련된 이전 실행 지시 문서가 있으면 그 파일명을 참조로 적는다.
2. **산출물 명세:** 산출물별 종류·개수·내용 범위·파일 형식·파일명 또는 명명 규칙·저장 및 제공 위치·필수 구성·수용 기준을 명시한다. 원본 보존·덮어쓰기 여부 및 개수가 달라지는 조건도 기술한다.
3. **작업 수행 명세:** 실제 수행할 작업을 계층형 항목으로 구분하고 각 항목에 변경 ID, 수정 위치, 적용 전/후 상태, 수정·생성 명령, 선행 관계, 필요한 근거, 보존·금지 조건, 검증·완료 기준, 예외 시 중단·보고 방법을 함께 기술한다. 작업 전체에 공통인 실행·검증·보고 조건은 제3절의 마지막 하위 절에 배치하고, 앞선 작업 항목에서 참조할 수 있다. 작업 완료 후 완료·부분 완료·미적용·실패의 구분, 근거, 실제 수정 위치 및 남은 문제를 보고하는 형식을 이 절의 공통 항목에 둔다. PROC-001 제8조제1항제9호의 실행 AI 준수 원칙도 누락하지 않는다.
4. **폐기·제외된 지시:** 실행 지시 문서의 작성 과정에서 폐기·제외된 제안·지시 중 재도입 방지가 필요한 것과 그 이유·제외 범위를 표로 정리한다. 해당 사항이 없으면 '해당 없음'으로 적는다.
5. **실행 제외 항목(선택):** PROC-001 제9조제2항에 따라 참고로 전달하는 미결·보류·검증 필요 사항을 둔다. 이 절의 내용은 실행 명령이 아니며, 실행 AI는 이를 수행하지 않는다.

각 절의 번호·제목·순서는 이 항의 각 호를 따르며, 절을 통합하거나 순서를 바꾸지 않는다. 제4호의 절은 해당 사항이 없으면 ‘해당 없음’으로 적고, 제5호의 절은 해당 사항이 없으면 절 자체를 생략한다.

③ **작업 수행 명세의 계층:** 제3절은 `3.1`부터 `3.n-1`까지를 개별 작업 항목으로 구성하고, 마지막 `3.n`을 **공통 실행·검증·보고 조건** 절로 둔다. `n`은 실제 하위 절 수에 따라 정하며 고정 번호 `3.2`를 강제하지 않는다. `3.1`, `3.1.1` 등 숫자 계층으로 식별하는 단위를 **작업 항목**이라 한다. 작업 항목은 필요에 따라 `3.1.1`까지 세분할 수 있다. 그보다 세밀한 내용을 나눌 필요가 있을 때 사용하는 `(1)`, `(2)`, `(3)` 등의 괄호 번호는 **세부 구분**이라 하며, 작업 항목으로 간주하지 않는다. 세부 구분은 필요한 경우에만 사용한다. 상위 항목은 작업 대상과 목표를, 하위 항목은 실제 수행 내용을 구체화한다. 각 항목에 필요한 근거는 원본과 대조 가능한 식별자 또는 출처로 연결하며, 불필요한 근거나 반복 설명은 생략한다.

④ **실행 대상의 한정:** 실행 지시 문서에는 결정 상태 표기를 두지 않으며, 각 작업 항목이 승인된 사실은 승인 참조로 나타낸다. 실행 지시 문서의 작업 수행 명세에는 승인되고 사전 검증이 완료되어 실행 대상으로 확정된 내용만 남긴다. `[삭제 확정]`은 기존 작업물의 실제 삭제가 승인된 경우에만 삭제 명령으로 작성한다.

⑤ **폐기·제외된 지시 표의 형식:** 제2항제4호는 Markdown 표로 작성하며 기본 열은 `일자 | 변경 대상 | 변경 내용 | 변경 이유 | 승인`으로 한다. 변경 이유에는 폐기·제외의 범위와 재도입을 경계해야 하는 조건을 명시한다. 이 표는 현행 지시를 이해하기 위한 참고 정보이며, 과거 지시를 실행하거나 복원하는 근거로 사용하지 않는다. 단순 오탈자 등 실행 판단에 영향이 없는 수정은 간략히 기록할 수 있다.

⑥ **정합성과 우선순위:** 제3절의 현행 실행 명령과 제4절의 폐기·제외된 지시가 상충하면 해당 항목을 임의로 해석하거나 수행하지 않고 상충 사항을 보고한다. 제4절의 기록으로 현행 본문의 승인 범위를 확대·축소하지 않는다.

⑦ **대응표의 작성 범위:** 부록 C의 대응표는 PROC-001 제8조제1항의 필수 지시 사항이 실행 지시 문서의 어느 위치에 반영되는지 확인하기 위한 점검표로서, 다음 각 호에 따라 작성한다.

1. 행은 PROC-001 제8조제1항의 각 호당 하나로 한정한다.
2. 열은 '해당 호 | 반영 위치 | 적을 요소'의 세 개로 하고, '해당 호'에는 호 번호와 짧은 이름을, '적을 요소'에는 핵심어만 적는다.
3. PROC-001의 조문 전문·예시·해설은 옮기지 않으며, 표 위에 '각 호의 세부 정의는 PROC-001 제8조제1항을 따른다'를 적는다.
4. 하위 요소는 제3절 작업 항목에 각각 기재해야 하는 경우에만 풀어 적는다.
5. 대응표는 반영 위치를 안내할 뿐 새로운 의무를 정하지 않는다. 대응표가 이 문서의 본문 또는 PROC-001과 다르면 본문과 PROC-001을 따르고 그 차이를 보고한다.

## 제5조(절·항목 및 표기)

① **제목 계층:** 문서의 제목과 본문 절은 Markdown 제목 문법을 사용하며, 문서 제목은 `#`, 본문 주요 절은 `##`, 제4조의 작업 항목 `3.1` 등은 `###`, 그 하위 작업 항목 `3.1.1` 등은 `####`로 표시한다. 제목 계층은 문서 구조를 나타내는 서식이며, 작업 항목 번호는 해당 작업을 식별하는 번호로서 서로 구분한다.

② **목록·표·예시 및 부록:** 실행 지시 문서에서는 다음 각 호에 따라 사용한다.

1. **번호 목록:** 실행 순서와 선후 관계가 있을 때 사용한다.
2. **글머리표:** 순서 없는 병렬 조건이나 참고 정보를 나열할 때 사용한다.
3. **표:** 같은 기준으로 비교하거나 산출물 명세·대응 관계를 보일 때 사용한다.
4. **예시:** 산출물이나 보고의 형식을 문장만으로 지시하기 어려울 때에만 사용한다. 예시임을 밝히고, 실제로 적용할 값·문안과 구분한다.
5. **부록:** 도구별 실행 방식(제2조제6항제3호)이나 반복 참조할 긴 자료에만 둔다. 부록은 본문에서 참조한 범위에서만 적용하며, 부록에 본문에 없는 실행 명령을 두지 않는다.

제4조제3항의 `(1)`, `(2)` 등 세부 구분은 별도의 Markdown 제목 계층을 만들지 않는다.

③ **식별자 표기:** 변경 ID·파일 위치·함수명·식 번호 등 추적에 필요한 식별자는 원문과 일치하도록 기재하며, 제2조제2항의 원문 유지 원칙을 따른다.

④ **표기 일관성:** 동일한 종류의 정보에는 문서 전체에서 일관된 표기 방식을 사용한다. 표·목록·제목 계층을 조정하더라도 작업 항목의 식별 번호와 참조 관계가 불명확해지지 않도록 한다.

## 제6조(변경 관리)

① **관리 대상의 구분:** 실행 지시 문서 작성 과정의 쟁점·결정·변경은 TPL-001에 따른 협업 작업 페이지의 변경 대장에서만 관리한다. 이 문서는 변경 대장의 열 구성을 정하지 않는다.

② **변경 대장에서의 이관:** 변경 대장의 내용은 다음 각 호에 따라 실행 지시 문서로 옮긴다.

1. 실행 대상인 `[확정]` 항목(`[검증 필요]`가 남은 항목 제외)은 제3절 작업 수행 명세로 옮긴다. 각 항목에는 PROC-001 제8조제1항에 따른 지시 내용과 함께 변경 ID, 실행에 필요한 간결한 이유, 승인 참조(확정자·일자)를 적고, 논의 경과와 대안 비교는 옮기지 않는다. 확정 과정은 변경 ID로 협업 작업 페이지에서 추적한다.
2. `[삭제 확정]` 항목 중 폐기된 제안·지시로서 재도입 방지가 필요한 것만 제4절에 이유와 제외 범위를 적고, 분리·통합에 따른 대체 항목은 옮기지 않는다.
3. 옮길 때는 변경 ID와 대상 위치를 유지하고, 내용은 명령형 지시로 바꾸며, 협업용 정보(작업 진행 상태·진행 현황 요약·남은 작업·색상)는 제외한다.

③ **변경 관리 원칙:** 변경 관리에서는 다음 각 호를 따른다.

1. 변경 대상이 다른 작업 항목·정의·참조·검증 기준에 영향을 미치면 PROC-001 제7조에 따라 연쇄 영향을 점검한다. 기존 기록의 ID·위치·링크를 활용하여 불필요한 중복 작성을 피한다.
2. 승인되지 않은 변경안과 승인된 실행 항목을 구분하고, 사용자의 승인 및 PROC-001 제4조의 상태 변경 요건을 충족하지 않은 내용을 임의로 확정하지 않는다.

④ **실행 지시 문서의 재작성:** 실행 지시 문서는 고쳐서 다시 내지 않는다. 수정이 필요하면 새로 작성하고, 관련된 이전 실행 지시 문서는 제1절에 참조로 적는다.

⑤ **폐기·제외된 지시의 작성:** 제4조제2항제4호와 제4조제5항에 따라 `일자 | 변경 대상 | 변경 내용 | 변경 이유 | 승인` 형식의 Markdown 표로 작성한다. '변경 대상'은 가능한 한 작업 항목 번호 또는 식별자로 연결하고, '승인'에는 사용자 승인 기록 또는 확인 가능한 참조를 기재한다. 폐기·삭제의 이유 및 현재 제외 범위는 실행 판단에 영향을 줄 때 명시한다.

⑥ **실행 명령과의 분리:** 제4절의 기록은 현행 지시를 이해하기 위한 참고 정보이며, 과거안을 복원하거나 실행할 권한을 부여하지 않는다. 현행 지시와 제4절의 기록 사이에 해소되지 않은 상충이 발견되면 PROC-001과 GOV-001의 중단·보고 원칙에 따라 처리한다.

## 제7조(문체 및 명령의 명확성)

① **명령형 작성:** 실행 지시는 명령형으로 작성하며, 다음 각 호의 기준을 따른다.

1. 실행 AI가 수행할 행동을 명확한 동사로 표현한다.
2. 명령에는 작업 대상, 수행 행동 및 요구 결과를 식별할 수 있도록 한다.
3. 완료 여부를 판단해야 하는 경우 구체적인 완료 조건 또는 검증 기준을 제시한다.
4. ‘적절히’, ‘가능한 한’, ‘필요에 따라’ 등 해석의 여지가 있는 표현에는 적용 조건이나 판단 기준을 명시한다.
5. 특정 표현이나 규정이 남지 않았음을 확인하는 검증 기준은 검사 범위(조·항·호·절 등)와 제거 대상의 의미(문장 또는 규정 단위)를 한정하여 쓴다. 같은 실행 지시 문서가 새로 넣도록 지시한 문장, 이력·인용 기록 및 입력 자료의 식별 정보는 검사에서 제외됨을 명시하며, 단어 단위의 문서 전체 검사는 그 단어가 문서 어디에도 남아서는 안 되는 경우에만 쓴다.

② **불확실한 정보의 처리:** 사실·가정·미결 사항과 실행 명령을 구분하며, 다음 각 호를 따른다.

1. 확인되지 않은 사실을 확정된 사실처럼 서술하지 않는다.
2. 작업 수행에 필요한 가정은 그 내용과 적용 조건을 명시하되, 가정만으로 미승인 작업의 실행을 허용하지 않는다.
3. 미승인·미결·사전 검증 필요 항목을 실행 명령으로 변환하지 않으며, PROC-001 제8조제3항에 따라 실행 대상에서 제외한다.
4. 실행에 영향을 미치는 불확실성이나 상충이 해소되지 않은 경우 해당 항목의 실행을 보류하고 이유·영향 범위·필요한 확인 사항을 보고하도록 명시한다.

③ **명령 동사와 권한의 구분:** 실행 AI가 수행할 행동과 허용 범위를 구별할 수 있도록 다음 각 호의 용어를 사용한다.

1. **검토:** 지정된 대상의 현황·문제·적합성을 살펴 판단 결과를 제시하는 행위. 검토 지시만으로 원본의 변경·삭제를 허용하지 않는다.
2. **수정:** 지정된 대상을 승인된 범위와 조건에 따라 변경하는 행위. 수정 지시만으로 대상 밖의 파일·절·기능 변경이나 원본 덮어쓰기를 허용하지 않는다.
3. **검증:** 결과가 지정된 요구사항과 판정 기준을 충족하는지 확인하는 행위. 검증 지시만으로 기준·임계값·대상·절차를 변경·완화·생략하거나 결과를 조작할 수 없다.
4. **보고:** 수행 상태, 근거, 실제 수정 위치 및 남은 문제를 정해진 형식으로 전달하는 행위. 보고 지시만으로 후속 수정이나 미승인 작업의 실행을 허용하지 않는다.

④ **근거 및 설명:** 실행에 필요한 근거와 설명만 포함하며, 다음 각 호를 따른다.

1. PROC-001에서 이루어진 대화·대안 비교·논의 경과를 원칙적으로 그대로 옮기지 않는다.
2. 작업 방법·요구사항·제약 조건의 이해에 필요한 이유는 간결하게 기술한다.
3. 근거 자료는 실행 AI가 확인할 수 있도록 출처·식별자·위치를 명시하고, 근거의 표기는 제1조제4항에 따라 TPL-003을 따른다. 근거 표기를 사용한 실행 지시 문서는 제3절의 공통 실행·검증·보고 조건에 사용한 표기의 뜻을 적는다.
4. 폐기된 제안과 그 이유는 현재 작업의 해석 또는 재도입 방지에 필요한 경우 제4조의 폐기·제외된 지시에 기록하고, 현행 실행 명령과 혼합하지 않는다.
5. 삭제

## 제8조(전달 대상 및 전달 단위)

① 주된 전달 대상은 GPT·Claude 등 **기존 대화 이력을 공유하지 않는 별도 실행 AI**를 원칙으로 한다.

② 전달 단위는 실행 지시 문서 및 실행에 필요한 원본·참조 자료, 승인·제외 범위와 검증·보고 요구사항으로 한다.

③ 전달 매체(Notion 링크, 파일 첨부, 저장소 경로 등)는 실제 접근 권한과 자료 재현 가능성을 확인하여 결정한다.

④ 실행 지시 문서의 작성·승인·전달은 실제 파일 수정이나 작업 실행의 자동 승인을 뜻하지 않는다.

⑤ **대체 전달 경로:** 실행 AI가 원본에 직접 접근하거나 원본을 수정할 수 없는 경우에는 다음 각 호에 따른다. 실행 AI가 사전 점검에서 접근 불가를 보고한 경우와 사용자가 처음부터 이 경로를 지정한 경우에 모두 적용한다.

1. 사용자는 원본과 참조 자료를 Markdown(`.md`) 파일로 전달한다. `.md`로 변환할 수 없는 자료는 원본 파일을 전달한다.
2. 실행 AI는 수정이 모두 반영된 전문을 전달받은 것과 같은 형식의 파일로 반환하며, 원본에 대한 반영은 사용자가 한다.
3. 이 경로를 사용할 수 있는 작업의 실행 지시 문서는 제2절 산출물 명세에 원본에 접근할 수 없을 때 반환할 문서의 형태(형식·파일명·제공 위치)를 함께 서술한다.
4. 변환 과정에서 바뀌거나 손실될 수 있는 요소는 실행 지시 문서의 보존 조건에 적고, 수정 대상이 아닌 변환 표기는 그대로 유지하도록 지시한다.

## 제9조(양식 점검 및 예외)

① 컴파일 완료 전 파일 형식, 머리말, 필수 절, 식별자, 산출물 명세, 접근 가능한 입력 자료, 특정 표현·규정이 남지 않았음을 확인하는 검증 기준이 같은 실행 지시 문서가 넣도록 지시한 내용이나 입력 자료와 상충하는지 여부, 지시의 독립 이해 가능성을 확인한다.

② 형식상의 편의를 이유로 GOV-001 및 PROC-001의 승인·검증·중단 요건을 완화하지 않는다.

③ 특수한 형식이 필요한 경우 예외의 필요성·적용 범위·호환성·승인 여부를 명시하고 별도로 논의한다.

## 부록 B. 미확정 설계 쟁점

- **TPL-002-Q01 [확정]:** 파일명 규칙을 고정할지, 식별 가능성만 요구할지 처리 결과: 본문은 바꾸지 않는다. 실행 지시 문서의 파일명은 제2조제4항으로 고정되어 있고, 산출물 파일명은 제2조제5항에 따라 실행 지시 문서마다 명시한다(도현, 2026-10-10).
- **TPL-002-Q02 [확정]:** 표준 절 9개의 제목·순서 고정 여부와 통합 허용 범위 처리 결과: 쟁점 문구의 ‘9개’는 과거 버전 기준이며 현행은 5개 절이다. 제4조제2항 끝에 절의 번호·제목·순서 고정과 통합·재배열 금지, 제4호·제5호 절의 처리에 관한 문장을 추가하였다(도현, 2026-10-10).
- **TPL-002-Q03 [확정]:** 문서 ID·작성일·상태 등 머리말의 필수/선택 구분 처리 결과: 머리말 필수 항목(작성 기준일·작업 목적·작업 범위)은 현행대로 둔다. 정의가 없던 문서 식별자 선택 항목(제3조제3항)은 삭제하되 항 번호는 유지하고, 제3조제6항의 선택 항목 생략 문구를 삭제하였다(도현, 2026-10-10).
- **TPL-002-Q04 [확정]:** 기본 전달 형식을 단일 `.md` 파일로 할지, 자료 묶음/링크도 표준화할지 처리 결과: 실행 지시 문서의 단일 `.md` 출력은 제2조제3항으로 정해져 있다. 자료 전달 방식은 표준화하지 않고, 원본에 접근·수정할 수 없을 때의 대체 전달 경로만 제8조제5항에 신설하였다(도현, 2026-10-10).
- **TPL-002-Q05 [확정]:** 번호 목록·표·예제·부록의 권장 사용 기준 처리 결과: 제5조제2항을 번호 목록·글머리표·표·예시·부록의 사용 기준을 정한 5개 호로 교체하였다(도현, 2026-10-10).
- **TPL-002-Q06 [확정]:** TPL-003과의 근거 표기 적용 범위 충돌. TPL-003 제4절제1항은 사실 근거 문장에 `[종류 - 등급]` 병기를 요구하고 실행 지시 문서를 예외로 두지 않으나, 제7조제4항제3호는 실행 지시 문서에 그 표기를 옮기지 않는다고 정한다. 해결 후보는 TPL-003 후속 개정(v1.1)에서 실행 지시 문서의 예외를 두는 것이다. 발견 경위: 초안 v0.2 실행 보고의 전 조항 점검(2026-10-09). 처리 결과: 충돌을 TPL-002 쪽에서 해소하였다. 제1조제4항에 TPL-003 의존성을 명시하고, 제7조제4항제3호를 TPL-003을 따르도록 고쳤으며, 표지를 정하던 제7조제4항제5호를 삭제하였다. 근거의 신뢰도 서술은 TPL-003 후속 개정에서 정비한다(도현, 2026-10-10).
- **TPL-002-Q07 [확정]:** 검증 기준의 잔존어 검사 작성 방식. ‘~가 남지 않을 것’ 같은 검사를 단어 단위로 넓게 쓰면 정당한 표현이나 같은 문서가 넣도록 지시한 문장과 충돌한다. 검사 대상(조문 범위·의미)을 한정하여 쓰는 기준을 제7조제1항제3호 등에 둔다. 발견 경위: 초안 v0.2 실행 보고에서 실행 AI가 검증 기준 충돌 3건을 보고함(2026-10-09). 처리 결과: 제7조제1항제5호에 부재 확인형 검증 기준의 작성 기준을 신설하고, 제9조제1항의 컴파일 전 점검 대상에 그 기준과 다른 지시·입력 자료의 상충 여부를 추가하였다(도현, 2026-10-10).
- **TPL-002-Q08 [제기]:** 부록 B 제목의 정비. 부록 B의 제목은 ‘미확정 설계 쟁점’이나, 초안 v0.3에서 수록 쟁점 Q01~Q07이 모두 확정되어 제목과 내용이 맞지 않는다. 부록 B는 쟁점이 모두 확정되어도 삭제하지 않으므로(작업공간_TPL002수정 3.5), 확정된 쟁점도 포괄하는 제목으로 바꾸는 방안을 검토한다. 발견 경위: 초안 v0.3 실행 결과 검증(2026-10-10).
- **TPL-002-Q09 [제기]:** 처리 결과 기록의 구분 방식. 쟁점 문구 뒤에 공백 한 칸을 두고 처리 결과를 이어 적는 방식(작업공간_TPL002부록B처리 3.9)으로 인해, 마침표 없이 끝나는 Q01~Q05의 문구가 ‘…요구할지 처리 결과:’처럼 이어져 읽기 어렵다. 처리 결과를 줄을 바꿔 하위 항목으로 적는 등 구분 방식을 정한다. 발견 경위: 초안 v0.3 실행 결과 검증(2026-10-10).

> 위 쟁점 중 미확정 쟁점은 각 결정 상태로 유지하며, 사용자와 AI의 합의 없이 상태를 변경하지 않는다.

- **초안 v0.2 — 2026-10-09:** 협업 작업 페이지 '작업공간_TPL002수정'에서 확정된 변경(CHG-001·002·004~011·013·014)을 반영. 제목을 'TPL-002 — 실행 지시 문서 작성 규칙'으로, 머리말 표지를 '규칙 지위'로 바꾸고 기준 문서(GOV-001 v2.3, PROC-001 v1.9, TPL-001 v1.0, TPL-003 v1.0)를 명시. 대상 문서 명칭을 '실행 지시 문서'로 통일. Notion 작성 과정에 관한 규정과 상태 색상 규정을 삭제하고 특정 도구 요소 금지를 제2조제6항제2호로 일원화. 실행 지시 문서의 가안 단계·문서 상태·버전 표기를 삭제하고 작성 기준일을 필수로 하며, 제4절을 '폐기·제외된 지시'로 변경. 제6조를 변경 대장과의 관계 중심으로 교체. 근거 표기에 `[미확인]`·`[가정]` 표지를 도입. 제4조제7항(대응표의 작성 범위)과 부록 C(필수 지시 사항 대응표)를 신설하고 종전 부록 C(제정 이력)를 부록 D로 이동. 부록 B 쟁점 ID를 TPL-Q01~Q05에서 TPL-002-Q01~Q05로 변경(쟁점 내용은 변경 없음). 초안 v0.1의 의존 버전은 기록되지 않음. 승인 기록: 도현, 2026-10-09.
- **초안 v0.3 — 2026-10-10:** 협업 작업 페이지 ‘작업공간_TPL002부록B처리’에서 확정된 변경(CHG-001~011)을 반영. 부록 B의 TPL-002-Q01~Q07을 모두 처리하고 처리 결과를 기록. 제1조제4항에 TPL-003 의존성을 명시하고 근거의 신뢰도 서술을 TPL-003으로 이관(제7조제4항제3호 개정, 제5호 삭제). 제3조제3항(문서 식별자)과 제3조제6항의 선택 항목 생략 문구를 삭제하고 항 번호는 유지. 제4조제2항에 절 구성 고정 문장을 추가하고, 제5조제2항을 목록·표·예시·부록의 5개 호로 교체. 제7조제1항제5호(부재 확인형 검증 기준) 신설, 제8조제5항(대체 전달 경로) 신설, 제9조제1항에 검증 기준 상충 점검 추가. 부록 A 첫 설명의 ‘최종 지시’를 ‘실행 지시 문서’로, 3.n의 근거 항목을 근거 표기 항목으로 수정. 이번 개정의 실행 지시 문서는 TPL-002 초안 v0.2 양식을 시험 적용하여 작성됨. 승인 기록: 도현, 2026-10-10.
