# AI 협업 운영 체계 (GOV · PROC · TPL)

사람과 AI(GPT, Claude 등)가 함께 작업할 때 **누가 무엇을 결정하고, 무엇이 승인되었으며, 무엇을 실행해도 되는지**를 명확히 하기 위한 문서 체계입니다.

## 왜 만들었나

AI와 협업하다 보면 다음과 같은 문제가 반복됩니다.

- AI가 근거를 확인하지 않은 내용을 사실처럼 쓰거나, 사용자가 승인하지 않은 방향을 임의로 확정한다.
- 논의 중이던 아이디어가 어느새 실행 지시로 바뀌어 산출물에 반영된다.
- 대화가 길어지면 이전 결정이 흐려지고, 다른 AI나 새 세션에서는 같은 결과를 재현하기 어렵다.

이 체계는 이런 문제를 **원칙(GOV) → 절차(PROC) → 양식(TPL)** 의 문서 구조로 통제하려는 시도입니다.

## 문서 구성

| 식별자 | 문서 | 역할 | 상태 |
|---|---|---|---|
| GOV-001 | [협업 운영 규칙](gov/GOV-001.md) | 결정권·승인·근거·기록·검증·변경 통제의 공통 원칙 | v2.2 |
| PROC-001 | [지시 문서 작성 운영 규칙](proc/PROC-001.md) | 논의를 거쳐 실행 가능한 지시 문서를 작성하는 절차 | v1.8 |
| PROC-002 | 작업 실행·검증 절차 | 승인된 지시 문서에 따른 실행과 검증 | 미제정 |
| TPL-001 | 작업 문서 양식 | 작업 기록·지시 문서의 표준 골격 | 계획 중 |

- **GOV** = Governance (공통 원칙), **PROC** = Procedure (업무 절차), **TPL** = Template (양식)
- 번호는 식별번호이며 상하 위계를 뜻하지 않습니다.

## 핵심 설계 원칙

- **결정권은 사용자에게:** AI는 제안·검증·정리를 맡고, 확정은 사용자의 명시적 승인으로만 이루어진다. 침묵은 승인이 아니다.
- **논의와 실행의 분리:** 논의 종결, 지시 문서 작성 완료, 실제 작업 실행은 각각 별도로 승인한다.
- **조건부 실행 금지:** 미결이거나 사전 검증이 남은 항목은 조건을 붙여 실행 대상에 넣지 않고 제외한다.
- **근거 등급 표기:** 사실과 해석·가정·다른 AI의 출력·사용자 진술을 구분하고, 근거에 종류와 신뢰도 등급을 붙인다.
- **플랫폼 독립:** 특정 AI 서비스의 기능에 의존하지 않고, 대화 이력 없이도 다른 AI가 지시 문서를 이해하고 실행할 수 있게 한다.

## 원본과 버전 관리

- 문서의 작업 원본은 Notion에 있으며, 이 저장소는 버전이 확정된 시점의 공개 사본입니다.
- 각 문서의 개정 이력은 문서 하단에 기록되어 있습니다.
