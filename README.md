# AI 협업 운영 규칙 (AI Collaboration Governance)

사용자와 AI(GPT·Claude 등)가 함께 작업할 때 적용하는 협업 규칙과, 그 규칙에 따라 만든 실행 지시 문서를 보관하는 저장소입니다.

- **규칙 원문은 Notion에서 관리합니다.** 이 저장소는 규칙의 구성과 현황을 안내하고, 실행 AI에게 전달한 실행 지시 문서(`.md`)를 보관합니다.
- 규칙의 최신 버전과 개정 이력은 각 Notion 페이지의 머리말과 개정·제정 이력에서 확인합니다.

## 규칙 체계

규칙은 식별자로 종류를 구분합니다. 숫자는 같은 종류 안에서 규칙을 구분하는 번호이며, 위계나 우선순위를 뜻하지 않습니다(GOV-001 제1조).

| 식별자 | 종류 | 역할 |
| --- | --- | --- |
| GOV | Governance(협업 운영 원칙) | 역할·권한·승인·기록·근거·검증·변경 통제의 공통 원칙 |
| PROC | Procedure(업무 절차) | 단계별 진행 순서, 판단·승인 요건, 완료·이관 기준 |
| TPL | Template(작성 환경·양식) | 협업 페이지·문서의 구성, 표기, 작성·출력 양식 |

## 작업 흐름

1. **논의 (PROC-001):** 사용자와 설계 AI가 Notion 협업 작업 페이지(TPL-001 양식)에서 쟁점을 정리하고 결정합니다. 쟁점마다 `[제기] → [논의 중] → [확정]` 등의 상태를 두며, 상태 변경은 사용자와 AI가 모두 동의할 때만 합니다.
2. **종결 점검:** 결정 상태·최종 범위·기록 정합성·미결 처리·이관 가능성을 확인하고, 사용자가 최종 범위를 승인하면 논의를 종결합니다.
3. **컴파일:** 확정된 내용만 실행 지시 문서(`.md`, TPL-002 양식)로 작성합니다. 미결·검증 필요 항목은 실행 대상에서 제외합니다.
4. **보관:** 실행 지시 문서를 `work-orders/`에 넣고 사용자가 커밋·푸시합니다.
5. **실행 (PROC-002):** 대화 이력이 없는 별도 실행 AI가 실행 지시 문서만 보고 작업하고, 정해진 형식으로 보고합니다.
6. **검증:** 사용자와 설계 AI가 협업 페이지의 변경 대장을 기준으로 결과를 대조합니다.

논의 종결이나 실행 지시 문서의 작성만으로 실제 작업 실행이 승인된 것으로 보지 않습니다.

## 저장소 구성

```text
└── work-orders/      # 실행 지시 문서 보관
```
