## 3. 작업 수행 명세

다음 3.1~3.9는 협업 페이지의 같은 번호·CHG-ID에 대응한다. 3.10은 공통 조건이다. PROC 정합화는 CHG-001에 연결된 후속 승인 범위이며 별도 쟁점·건수로 중복 계산하지 말라.

### 3.1 상위 상태·자동 논의 시작·검증 플래그 및 PROC-001 정합화

변경 ID·승인: CHG-001 / 협업 페이지 3.1 / 도현·AI 동의, 2026-10-10. PROC 정합화 포함은 이번 후속 사용자 선택이다.

수정 위치: TPL-001 제4조제4항 말미·부록 A 상태 안내, PROC-001 제4조제1항제1·2·5호·제2항제1·2호·제3·4항·제5항 신설, 부록 B 상태 안내. 개별 내용 승인·삭제 승인 요건은 유지하라.

TPL-001에 다음 확정 문안을 추가하라.

> 상위 작업 항목 자체에 별도의 논의가 있는 경우에는 그 논의가 확정되고 모든 하위 작업 항목의 결정 상태가 각각 [확정] 또는 [삭제 확정]일 때, 별도의 사용자 승인이나 상태 변경에 대한 개별 동의 없이 상위 작업 항목을 [확정]으로 표시한다. 상위 작업 항목 자체에 별도의 논의가 없는 경우에는 모든 하위 작업 항목의 결정 상태가 각각 [확정] 또는 [삭제 확정]일 때 같은 방식으로 표시한다. 이 표시는 이미 결정된 논의의 상태를 종합한 것으로서 새로운 내용·범위 또는 실행을 승인하거나 실제 작업의 완료를 뜻하지 않는다.

> 사용자가 AI와 작업 항목에 관한 논의를 직접 시작하면 해당 작업 항목을 별도의 상태 변경 승인이나 개별 동의 없이 [논의 중]으로 표시한다. 하위 작업 항목 중 하나라도 [논의 중]으로 변경되면 상위 작업 항목도 함께 [논의 중]으로 표시한다. 이미 [확정]인 항목에서 논의가 다시 시작되는 경우에도 같은 방식으로 표시하되, 기존 확정 내용과 승인 기록은 보존하고 재논의 대상을 구분하여 기록한다. 이 상태 변경 자체를 기존 승인 내용의 변경이나 새로운 실행 승인으로 보지 않는다.

> [검증 필요]는 검증이 필요한 해당 작업 항목에만 표시하고 상위 작업 항목으로 자동 전파하지 않는다. 하위 작업 항목이 [확정][검증 필요]인 경우 결정 상태는 [확정]이므로 상위의 자동 확정 조건을 판단할 때 확정된 하위 항목으로 본다. 상위의 확정 표시는 하위의 검증 완료를 뜻하지 않는다.

> 선행 결정 대기인 작업 항목도 사용자가 실제 논의를 시작하면 [논의 중]으로 표시하고, 미해결 선행 쟁점 ID·의존 이유·제약은 별도 기록으로 유지한다. 논의 중 전환으로 선행 조건이 해결된 것으로 보지 않는다. 아직 논의를 시작하지 않은 의존 항목은 [선행 결정 대기]를 유지한다. 하위 항목이 없는 작업은 자체 논의의 상태 기준을 따른다. 여러 단계의 상위 항목에는 같은 기준을 각 단계에 적용한다.

상태 글자색·계층·세부 구분 기준은 유지하라. 부록 A에는 위 원칙과 TPL 제4조제4항·PROC 제4조의 연결을 안내하라. 하위가 모두 삭제 확정이라고 상위 자체 삭제 결정을 만든 것으로 취급하지 말라.

> ⑤ **자동 상태 표시의 예외:** 사용자가 AI와 해당 작업 항목의 논의를 실제로 시작하면, 상태 변경을 위한 별도 사용자 승인이나 사용자·AI의 개별 동의 없이 [논의 중]으로 표시한다. 단순 언급과 실제 논의 시작을 구분한다. 선행 결정 대기 항목도 실제 논의가 시작되면 같은 방식으로 표시하되 미해결 선행 쟁점 ID·의존 이유·제약은 별도 기록으로 유지한다. 하위 중 하나라도 [논의 중]이면 각 상위 항목도 [논의 중]으로 표시한다. 상위 자체 논의가 있으면 그 논의도 확정되고 모든 하위 항목이 각각 [확정] 또는 [삭제 확정]일 때, 상위 자체 논의가 없으면 모든 하위가 두 상태 중 하나일 때, 별도 승인·개별 동의 없이 상위를 [확정]으로 표시한다. 하위 없는 항목은 자체 논의 상태를 따른다. 확정 항목의 재논의에서도 기존 승인·확정 기록을 보존하고 재논의 범위를 구분한다. [검증 필요]는 해당 항목에만 표시하고 상위로 자동 전파하지 않으며, 확정에 덧붙은 이 플래그는 상위의 종합 확정 판단을 막지 않지만 하위의 검증 완료를 뜻하지 않는다. 이 항은 상태 표시 절차의 예외이며 새로운 내용·범위의 승인, 삭제 실행, 검증 완료 또는 실제 작업의 실행·완료를 대신하지 않는다. 표시 형식과 계층별 적용은 TPL-001 제4조제4항(참조 기준 v1.1)을 따른다.

제4조제2항제3호 양방향 의존성 기록과 제5·8·9조의 미결·검증 필요 실행 제외·내용 승인·이관 요건을 변경하지 말라. 부록 B에는 제4조제5항 참조와 미해결 선행 조건 기록 안내를 추가하되 새 필수 표를 만들지 말라.

선행 관계: 두 규칙을 한 변경 묶음으로 맞추라. 한쪽만 반영하여 정합성이 깨진 상태를 완료로 보고하지 말라. 저장 문제가 생기면 중단하고 실제 적용 위치·미적용 위치를 보고하라.

검증: 상위 자체 미결·확정·논의 없음, 하위 모두 확정·삭제 확정 혼합·모두 삭제 확정·미결 존재·하위 없음, 직접 논의 시작·단순 언급, 대기 직접 논의·미시작, 여러 단계 전파, 확정 후 재논의, 확정+검증 필요를 대조하라. 표시 예외와 개별 내용·실행 승인을 구분하라. 나머지 상태 변경을 자동화하지 말라.

### 3.2 논의·결정 현황과 실제 작업 현황 분리

변경 ID·승인: CHG-002 / 협업 페이지 3.2 / 도현·AI 동의, 2026-10-10.

수정 위치: 제4조제5항제3호의 분리·통합 집계 안내, 제4호의 진행 현황 요약, 부록 A 제4절 요약표·집계 안내.

현행은 완료·미착수를 작업 진행 상태로, 진행 중을 결정 상태로 세는 혼합 요약이다. 두 현황을 별도 표로 분리하라.

논의·결정 현황에 다음 확정 문안을 반영하라.

> 논의·결정 현황과 실제 작업 현황을 구분하여 요약한다. 논의·결정 현황의 미착수는 결정 상태가 [제기] 또는 [선행 결정 대기]인 항목의 건수, 진행 중은 [논의 중]인 항목의 건수, 완료는 [확정] 또는 [삭제 확정]인 항목의 건수로 한다. 논의·결정 현황에는 보류를 두지 않는다. 집계 대상은 대장의 중복 없는 최하위 작업·변경 단위로 하며 삭제 확정을 전체와 완료에 모두 포함한다. 논의 완료율은 (확정 건수+삭제 확정 건수)/전체 건수×100%로 계산하고, 전체가 0이면 ‘해당 없음’으로 표시한다. 검증 필요는 해당 항목의 별도 플래그로 관리하고 세 단계 분류를 바꾸지 않는다. 이 집계는 결정 상태의 요약이며, 항목별 본문과 대장의 원래 결정 상태를 세 단계 명칭으로 바꾸지 않는다. 논의·결정의 완료와 실제 작업의 완료는 구분한다.

실제 작업 현황은 작업 진행 상태의 미착수·진행 중·완료·보류를 기준으로 요약하라. 현행의 제안 폐기·작업 제외·대체 항목 제외, 실제 삭제 작업 포함, 검증 필요의 별도 중복 플래그, 건수 기준 완료율·0건 ‘해당 없음’ 기준을 보존하라. 보류 건수는 별도 기재하여 빠진 건수가 추적되게 하라. 논의 현황의 ‘보류 없음’을 실제 작업 보류 폐지로 확대하지 말라.

제4조제5항제3호와 부록 A의 ‘분리·통합된 기존 항목 집계 제외’ 안내는 **현재 실행 작업·실제 작업 현황**의 제외로 한정하라. 논의 현황에서는 삭제 확정도 포함한다는 구분을 넣어 상충을 해소하라. 승인 기록·원래 상태·기존 ID·양방향 대체 관계 보존은 유지하라.

검증: 전부 제기·미착수, 전부 확정·미착수, 확정·삭제 확정 혼합, 선행 결정 대기·논의 중 혼합, 보류·부분 완료·검증 필요, 0건 사례를 대조하라. 논의 현황 세 단계 합은 전체와 같아야 한다. 이 작업 페이지의 현재 논의 현황은 전체 9건·완료 9건·미착수 0건·진행 중 0건·100%이고, 원본 반영 작업은 완료 0건이다. 공통 조건과 상위 항목은 중복 집계하지 말라.

### 3.4 협업 페이지의 버전·지위 폐지 및 식별·변경 기록 정비

변경 ID·승인: CHG-004 / 협업 페이지 3.4 / 도현·AI 동의, 2026-10-10.

수정 위치: 제1조제1~3항, 제2조제4항, 제3조제2·3항, 제4조제2항제5호·제5항제3호·제6·7항, 제6조, 제8조제2항, 부록 A·D의 현행 협업 페이지 안내·예시.

다음 기준을 현행 작성·관리 문안에 반영하라.

- 협업 작업 페이지에는 문서 버전을 부여하거나 갱신하지 않고 가안·정식 지위를 구분하지 않는다. 개별 작업의 결정 상태·승인 기록·변경 대장은 유지한다.
- 페이지명은 `작업공간_작업목표_YYYYMMDD`로 한다. 날짜는 최초 작성일이며 이후 편집해도 바꾸지 않는다. 공백·대괄호를 쓰지 않는 현행 페이지명 기준은 유지한다.
- 머리말 필수 항목은 작성 기준일·작업 목적·작업 범위 순으로 한다. 작성 기준일은 최초 작성일이며 제목 날짜와 일치한다. 문서 버전·문서 상태 행은 없앤다. 문서 식별자는 선택 정보로 유지하고 필요한 경우 작성 기준일 앞에 둔다.
- 제5절 이름은 ‘협업 작업 페이지 변경 이력’으로 한다. 새 기록의 열은 `일자 | 변경 대상 | 변경 내용 | 변경 이유 | 사용자 결정·승인 참조`로 한다. 버전 열을 두지 않는다. 과거 변경 내용·폐기 이유·현재 제외 범위와 승인 추적은 유지한다.
- 같은 목표·같은 날짜의 페이지는 고유 페이지 ID·URL로 구분할 수 있다. 의무적인 번호·시각 접미사를 추가하지 말라. 매번 페이지를 새로 만드는 의무도 추가하지 말라.
- 최초 작성일은 최신 수정일이 아니다. 이후 편집일은 변경 이력에 기록한다. 후속 페이지가 기존 작업을 잇는 경우 기존 페이지·CHG-ID·승인 기록을 연결한다.

제6조의 제목을 ‘협업 작업 페이지의 변경 및 기록 관리’로 바꾸라. 제1·2항의 대장·기록·승인 추적 기능을 유지하면서 버전별 변화 표현을 수정하라. 제3·4항의 협업 페이지 Major/Minor 상승·가안/정식 승격 규정을 제거하고, 해당 위치에 각각 버전·지위를 두지 않는 기준과 최초 작성일·수정일 구분 기준을 기재하라. 제5항의 이력 표는 위 5열로 정비하고 제6항의 실행 명령 분리·상충 중단 기준은 유지하라. 기존 항 번호는 유지하라.

제1조의 협업 페이지 가안/정식·버전 관리 표현, 제4조제5항제3호의 ‘문서 버전이 바뀌어도’ 표현, 제4조제7항의 버전 기준 참조, 제8조제2항의 전달 내용 중 문서 버전은 위 기준에 맞게 정비하라. 실행 승인과 페이지 작성·전달을 구분하는 원칙은 보존하라.

부록 A·D는 날짜형 페이지명·3행 머리말·5열 변경 이력으로 맞추라. 부록 D 날짜 예시는 2026-10-08을 사용하고 제목 접미사도 `20261008`로 맞추라. 부록 A ‘작성 시 유의’의 버전·승격 안내도 새 기록 기준으로 바꾸라.

검증: 새 페이지·같은 날 편집·다른 날 편집·같은 날 동명 페이지·후속 페이지 연결을 점검하라. 현재 작성 기준을 정하는 지정 위치에 협업 페이지의 버전 부여·상승·가안/정식 승격 의무가 남지 않아야 한다. 규칙 자체 머리말의 개정 버전, 부록 B·C의 과거 버전 표현, 입력 식별 정보, ‘버전을 부여하지 않는다’는 새 문장은 제거 검사에서 제외하라. 규칙 자체의 버전 제도를 폐지하지 말라.

두 규칙 개정·검증 후 현재 협업 페이지를 같은 ID·URL에서 `작업공간_TPL001부록B처리_20261010`으로 맞추라. 머리말과 새 이력은 위 날짜형 기준으로 정비하라. 기존 버전별 이력은 역사 기록으로 별도 보존하여 버전 표지·승인·내용을 잃지 않게 하라. 최초 작성일 2026-10-10은 고정하고 실제 수정일은 이력에 남기라.

예외 처리: 위치·원문·승인 불일치, 입력 누락, 해소되지 않은 상충, 문서 손실 또는 검증 불가가 있으면 해당 항목을 중단하고 이유·영향·필요한 자료·결정을 보고하라. 미결을 임의 해결하거나 제외된 작업을 되살리지 말라.

실행 AI 준수 원칙(PROC-001 제8조제1항제9호, 상세 GOV-001 제9조):

- 작업이 불가능하거나 필요한 검증을 수행할 수 없으면 제한을 임의로 우회하거나 검증되지 않은 대체 결과를 완료·검증 성공으로 보고하지 말라. 해당 작업을 중단하고 이유·영향 범위·필요 조건을 보고하라.
- 결과를 통과시키기 위해 검증 기준·임계값·검증 대상·절차를 임의로 변경·완화·생략하지 말라. 검증 데이터·결과·판정을 조작하지 말라.

근거 표기: `[원자료·실험 기록 - B]`는 직접 읽은 원본 기록이 명시된 상태·문구를 뒷받침함을 뜻하며 기본 등급을 사용한다. `[사용자 진술 - N]`은 원자료로 확인하지 못한 사실 진술의 확인 단서이다. 사용자 결정·승인과 현재 AI의 설계·판단은 외부 사실 근거 등급으로 평가하지 말라. 자세한 취급은 TPL-003을 따르라.
